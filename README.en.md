# Night Watch

[中文](README.md) · [English](README.en.md)

A portrait-mode pixel-art auto-battler deckbuilder: place cards on an 8-slot board, merge them to higher tiers, and lean on adjacency synergies and chain triggers to hold the wall through nine long nights.

The same build ships as a web game (Vercel) or inside a Capacitor native shell for iOS / Android.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fabcdlsj%2Fnightwatch&project-name=nightwatch&repository-name=nightwatch)

## Features

- An 8-slot board; cards are small / medium / large (1 / 2 / 3 slots), with adjacency and position affecting synergy.
- Tier merging: Bronze → Silver → Gold → Diamond, with damage / cooldown / hybrid upgrade paths.
- Three random event stops each night; nights 4, 8 and 9 bring elites and bosses, with five rotating final bosses.
- Five heroes (Ayla / Mo / Ying / Jun / Li), each with three archetypes and their own story.
- Endless nights, mastery, 8 difficulty tiers, a codex, and 31 achievements.
- Once a hero has reached dawn with all three archetypes and unlocked difficulty 5, two opt-in variants open up: omens (a run-wide rule picked from three) and archetype rotation (one home archetype drops out, a guest archetype from another hero joins).
- Reproducible rule RNG — same seed and inputs give the same result; combat simulation is UI-independent.
- Full localization packs, offline PWA, and a Capacitor native shell.

## Tech stack

TypeScript + Vite. UI is plain DOM, the battlefield is Canvas 2D (a low-resolution pixel canvas scaled up), and all music and SFX are synthesized live with WebAudio.

## Getting started

Requires Node 20.19+.

```bash
npm install
npm run dev        # dev server with hot reload
npm run build      # build to dist/ (this is what Vercel deploys)
npm run preview    # preview the build locally (port 4317)
npm run check      # typecheck + unit tests + build; run before committing
npm run e2e        # smoke test: a bot plays one run (build first; needs npx playwright install chromium)
```

Append `?seed=<number>` to the URL to pin the seed.

```
  main.ts             entry: wires up layers, bottom bar, main loop
  core/               RNG (reproducible), utilities, event bus
  platform/           storage, haptics, runtime (web / native shell)
  data/               pure data: cards, relics, talents, enemies, events, heroes, meta; art/ holds pixel art
  locales/zh-CN/      all text: content, shared story (story.ts), UI strings; story/ holds per-hero stories
  i18n/               t() and language switching; fills text into data tables at boot
  game/               rules: state, damage formula, loot, prep, save, meta progress; plan.ts schedules nights, story.ts picks story
  sim/                combat sim: spawns, chain triggers, damage, enemy AI, trigger hooks
  render/             visuals: sprites, battlefield canvas, background shader, overlay effects
  audio/              SFX, background music, audio toggles
  ui/                 UI components: cards, top bar, sheets, story, report, codex, voices
  app/                flow: start → prep → battle → result; prep/ holds prep actions, views and drag
  mod/                mods: types, validation, merging into tables, loading from mods/
  styles/             styles split by UI area
tests/
  unit/               locale completeness, layer boundaries, headless combat sim (vitest)
  e2e/                smoke test and key-screen screenshots (Playwright)
mods/                 mods (one per subdirectory; _example is a sample and is not loaded)
tools/                pixel art generation, font subsetting, missing-glyph checks, icon generation
docs/                 modding guide, balance notes, font licenses
```

## Layering

The rules and simulation layers never touch the DOM, so renderers and platforms can change without touching them. `tests/unit/layers.test.ts` enforces this:

| Layer | May depend on |
| --- | --- |
| `core` | nothing |
| `data` | `core` |
| `i18n` / `locales` | `data`, `core` |
| `game` | the above + `platform` |
| `sim` | the above + `game` |
| `render` / `audio` / `ui` / `app` | everything |

The combat sim reports presentation events (particles, floating text, SFX, barks, card flashes…) through the `SimView` interface in `sim/view.ts`; `ui/battle-view.ts` implements it, and headless runs use a no-op implementation.

RNG comes in two flavors: rule-relevant rolls (spawns, shop, loot, crits…) use `rng` from `core/rng.ts` and are reproducible; purely cosmetic ones (particles, floating text, which bark to pick) use `vr()` and never affect results. Saves record the RNG state from before prep.

## Internationalization

- Every on-screen string lives in `src/locales/zh-CN/`: `cards` `relics` `talents` `enemies` `events` `heroes` are content text, `story` holds story and barks, `terms` holds terminology, `meta` holds achievements, difficulties and modifiers, and `ui` holds interface strings.
- Data tables (`src/data`) hold mechanics only, never text; at boot `i18n/apply.ts` fills text in, and code reads `ITEMS[k].n` as usual.
- UI strings use `t('prep.refresh', { n: 2 })`, with `{n}` placeholders.
- To add a language: copy `locales/zh-CN`, translate, register it in `PACKS` in `i18n/index.ts`, then extend the font subset. `tests/unit/i18n.test.ts` checks for missing keys.

## Web & PWA

The web build is a PWA: open it in Safari on iPhone and tap "Share → Add to Home Screen"; Chrome on Android offers to install. Launched from the home screen it runs fullscreen with no browser chrome and works offline.

- `public/manifest.webmanifest`: name, portrait orientation, icons (`public/icons/`, generated by `node tools/make-app-assets.mjs`).
- `public/sw.js`: offline cache. Pages go network-first, hashed assets are served straight from cache, and each build bumps a cache version (`__BUILD_ID__`). Registered only for production web builds.
- When launched from the home screen, `<html>` gets a `standalone` class; `src/platform/pwa.ts` handles the iOS Safari install hint.

## Mobile (iOS / Android)

The native shell uses Capacitor, with projects in `ios/` and `android/` and config in `capacitor.config.ts` (appId `com.abcdlsj.nightwatch`).

```bash
npm run build && npx cap sync     # sync dist/ into the native projects
npx cap open ios                  # open in Xcode: run on a device / Archive to ship
npx cap open android              # open in Android Studio (Android SDK required)
```

- Portrait only; notches and rounded corners are handled with CSS safe-area-inset.
- Native saves go to system storage (`@capacitor/preferences`), migrating old WebView data on first launch; haptics use the system engine; audio mutes when backgrounded; Android's back button closes sheets and the inventory first. All of this is in `src/platform/native.ts` and is not loaded on the web.
- Icons and splash screens: `node tools/make-app-assets.mjs` generates the `resources/` sources and web icons, then `npx @capacitor/assets generate --ios --android --assetPath resources` exports every native size.

## Modding

Game content lives in tables: cards `ITEMS`, relics `RELICS`, talents `TALENTS`, enemies `EN`, heroes `HEROES` / `KITS` / `PATHS`, speakers `VOICES`, pixel art, and story. Rules code only works from table fields. Mods (`mods/<dir>/index.ts`) are loaded at boot by `src/mod/load.ts`, and `src/mod/apply.ts` validates and merges each entry into those tables; invalid entries are skipped, with reasons shown under "Workshop" on the title screen.

See [docs/modding.md](docs/modding.md) for the guide and `mods/_example/` for a sample. (Docs are in Chinese.)

## Art pipeline

Card icons, hero portraits and boss art are all drawing functions in `tools/pixelgen.py`. After editing them, run:

```bash
npm run art                              # regenerate src/data/art/generated.ts
python3 tools/pixelgen.py --preview      # also output previews under shots/ (requires Pillow)
```

## Development conventions

- One commit per change; use `type(scope): summary`, e.g. `feat(enemy): add a bomber rat`.
- Run `npm run check` before committing, and `npm run e2e` for larger changes.
- Add new text only under `src/locales`; when new Chinese characters appear, `npm run build` reminds you to run `npm run fonts`.
- `dist/` is build output and is not committed.
